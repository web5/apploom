§1.5 §4.2
面试题

首选：B3、B4、D4
备选：专项 Q6
术语：#1 静默失败

机制层讲法

空内容和「任务完成」在 HTTP 层都是 200，不显式判定就会被当成功写进记忆、流给用户。所以必须在引擎层把「无内容且无工具调用」升格为独立的失败类别，并配独立错误码，下游才能区分。

L3 边界

条件里要求「且无工具调用」：模型只发起工具调用、本轮正文为空是合法的。允许空输出的任务不能一刀切。另外这里只负责「发现」，我在 agent-core/src 搜 retry|maxRetries|backoff 没有命中（对照组 maxSteps 同法可命中），也就是没有自动重试。

量化数据

无

备选：专项 Q8

机制层讲法

机制层讲法

R10重试决策权在模型手里（幂等缺失）部分核实
现象

工具失败信息作为 tool 结果回灌给模型，模型自己决定要不要再调。引擎层没有 retry 与 backoff 逻辑。长任务插件超时返回 success:false，而后端任务其实仍在跑。

证据
  • core/agent-engine.ts:326、:332：失败回灌 工具执行失败: ...
  • plugins/long-running.ts:184-186：超时返回 success:false，error 文案含「可稍后用 get_job_status 继续查询」
  • agent-core/src 内搜 retry|maxRetries|backoff 无命中（对照组 maxSteps、AbortSignal 同法可命中）
  • 没有线上「同一流水线被发了两次」的事故记录；这条事故链是推演。而且返回文案已提示继续查询，实际重复概率比推演更低，要诚实讲

机制层讲法

Agent 里重试的决策权在模型手里，引擎只封顶步数，不管重试的性质。success:false 对人是提示，对模型是行动指令，所以写操作要有幂等键，并在返回值里区分「失败」与「还没出结果」。
